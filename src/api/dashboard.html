HPR stops calling this service for a route while it backs off after a failed request (1s, doubling to 5 min). With fail_on_unavailable on, it drops those packets, so they appear here as silences in otherwise steady traffic.
HPR also waits for this service before forwarding each copy to your LNS. A late copy reached us more than the LNS dedup window (lns_dedup_window) after the first copy of the same packet, so the LNS likely logged it as a retransmission. 3s or more later, a copy from a hotspot that already sent the packet is a device resend (the device didn't get its ACK); from a new hotspot it's a slow hotspot delivering its copy late.
